# A3 Agent 提示词

组员在各自已有 A1/A2 上下文的 Agent 中使用第一段，并提供最新 A3 要求。收齐候选方案后，将全部材料交给同一个 Agent，使用第二段。两段均不规定章节、字数或表格格式。

课程更新（2026-10-06）：使用最新V3及SAP API Pool v3；平台为OpenCode.ai + SAP APIs，交付ZIP。提示词供用户在合适阶段使用，不表示本轮已经派发Agent或选择方案。

## 1. 组员生成候选方案

```text
请阅读我的 A1/A2 和最新 A3 作业要求，基于我的路线提出一套 A3 App 候选实现方案，供之后另一位 Agent 与其他组员的方案比较。

先核对SAP API Pool v3与候选需求，说明API全匹配、部分匹配或不匹配及依据；按最新Option1/2/3保留同company/domain或改选边界，不把清单可用当作实际调用成功。

你可以自由探索和完善设计，自行决定原型范围、功能组合与表达结构，但要保留与原业务问题和解决方案的联系。方案应足够具体，让读者理解它解决什么问题、如何使用、如何在课程指定平台实现和验证，以及所需数据、工作量和主要局限。

用英文 Markdown 输出，保留关键依据，区分事实、假设与待验证内容。现在只形成候选方案，不直接开发，也不假设它已被小组选中。
```

## 2. Agent 比较并推荐方案

```text
请阅读所有组员的 A3 候选实现方案及最新作业要求，独立评估并推荐最适合实施的一套。

核对各候选的API适配路径和实际访问/包装验证依赖，区分V3已明确的OpenCode + SAP APIs/ZIP要求与尚未验证的运行细节。

自行组织分析，结合 Effort–Impact 和 A3 评分要求，使用一致的范围与标准比较业务价值、原型可行性、功能与可用性、演示效果、工作量和风险。核查影响结论的关键前提，不直接采纳各方案的自评；将企业潜在收益与课堂原型能证明的结果区分开，不把企业收益与原型工时混成同一个效益比较。

给出明确推荐、主要取舍，以及哪些缺失信息可能改变结论。可以提出对获选路线的改进，但保持一个核心方案。输出结构和篇幅由你决定，依据应可追溯，最终选择交由小组确认。
```
