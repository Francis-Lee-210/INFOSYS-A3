# Domain Docs

## Layout

Single-context:
- GLOSSARY.md at the repository root
- docs/adr/ for architectural decision records

## Consumer rules

Before exploring domain concepts, read GLOSSARY.md when present.
Read ADRs relevant to the area being changed.

If these files are absent, proceed silently. Domain-modeling creates
them when terminology or decisions are resolved.

Use the glossary's defined vocabulary in issues, proposals and tests.
Identify missing terms for domain-modeling when needed.

If a proposal conflicts with an ADR, identify the ADR and explain
why the decision should be reconsidered.
