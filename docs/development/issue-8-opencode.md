## Decisions and implementation

1. **Bounded pages, not accumulated history.** One visible page replaces the last; page changes invalidate detail, item checks, cost export and pending intention. Restart list is the explicit route back to page 1. Only up to 20 canonical page identities are tracked to stop cycles/unbounded traversal, never amount totals. An offline second fixture page makes the journey reproducible without a key.
2. **Resolve the continuation mismatch conservatively.** The frozen collection GET declares `$skip`, `$top`, `$select`, `$orderby`, filtering/count/expand. The existing validator allowed skip-token aliases while the transport refused them. A shared destination validator now supports only documented `$skip` plus the fixed read context: bounded top, JSON, exact projection and stable key order. It resolves allowed relative forms against the fixed collection and validates final origin/path/options before attaching a key. No offset is manufactured from row count. Unsupported skip-token/filter/expand/count contexts are rejected explicitly, not promoted into a speculative SAP contract.
3. **Preserve the read boundary.** GET-only, manual redirects, TLS verification, loopback Host/Origin checks, static-file allowlist and header minimisation remain. Header page bounds and 5 MiB streaming limits are enforced; optional item bounds/linkage stay intact. Item continuation metadata is not navigated; ambiguous duplicate metadata is withheld rather than counted as complete.
4. **Read recovery is not receipt retry.** Dedicated Retry read/Correct key/Back to connection controls operate on generation-bound list-page/detail-key/item coordinates, never a stored credential or receipt intention. Empty, authentication, timeout, network, rate-limit, service, redirect/navigation and contract/data states are distinct. A failed next-page load clears old rows and retries the same continuation. No live failure silently selects a fixture.
5. **Honest timing.** The adapter sanitizes integer delay-seconds and HTTP-date Retry-After (IMF-fixdate plus RFC850/asctime forms) into status/delay metadata, without returning the raw header. The UI uses a monotonic deadline and short feedback ticks, not a shortened server delay or automatic request. Missing/invalid 429 metadata gets an explicit one-second debounce; zero/past dates allow manual retry; unrepresentable delays remain blocked. Equivalent controls share the current cooldown. New key/source or deliberate disconnect/reset abandons the obsolete generation and timer.
6. **Session/provenance safety.** Live keys stay in memory/header transport, are replaced by explicit correction and cleared for auth rejection, fixtures, disconnect/reset/reload. Late results are consumed but ignored by generation/request checks; there is no automatic replay with an old key. Historical receipt provenance and bytes, v2 limitations, reset uncertainty and confirmation focus from #23 are retained without refactoring receipt storage.
